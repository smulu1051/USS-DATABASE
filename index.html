Data quality / migration checklist

  • Import actual tables from a source ACCDB or Access export; no source rows are loaded in this prototype.
  • Verify employee IDs and relationships between applications, employee, leave, training, exit and PPE records.
  • Validate leave balance calculations and approval rules against the original Access queries/forms.
  • Reconcile report totals against the original Leave Registery / Leave Report and other Access reports.

Data & Migration

Import/export prototype records and prepare for source database migration.

Source database requirement: the uploaded .ACCDB file is a Microsoft Access database. This environment can inspect embedded text labels, but does not currently have an Access database driver to enumerate tables and rows directly. This prototype cannot reliably reconstruct its editable form/query/VBA definitions or confirm every table relationship. For a faithful migration, provide the original .ACCDB source (if available) or export the tables and reports from Microsoft Access.

Access objects observed in file strings

Identifiable references include: ApplicationT, EmployeeT, Employee Leave, Employee Exit, Uniforms, qryEmployeeCount, Leave Registery, Leave Report, and forms labelled Employee Details, Employee List, Leave Form, Employee Leave, and Exit Details.

Application fields found in embedded strings include: Full Name, First Name, Last Name, Application Date, Reg Date, Status, Education, Email Address, Residence, Origin, Age, Height, Weight, Reference, Police Clearance, Medical Clearance, Bank Account, Recommendation, Experience, Knowledge, Communication, Problem Solving, Team Work, Organisational, Adaptability, Cultural Fit, Punctuality, Trainings, Driving Class, License Type, License Number, Issue Date and Expiry Date.

Employee / exit / leave references include: Employee ID, Job Title, Start Date, Number of Years, Department, CallSign, Employee Name, Leave Mode, Leave Start Date, Leave Due Date, Accrued Annual Leave, Accrued Sick Leave, Exit Date, Exit Mode, Exit Payment, Amount Paid, Paid Days, Approver Name, Endorser Name, Work Location and PPE.

These are string-level observations only, not a verified schema extraction. Field types, constraints, relationships, macros, business rules and full report definitions still require validation from the source database.
